# Submitting

**One submission per team. Due 2:30 PM.** The form is on the event hub. You can edit it until
2:30 by submitting again with the same team name and contact email.

**<https://claudesocal.com/uci-impact-lab>** (`#submit`)

## What to submit

1. **A public GitHub repo** with your code and a README that follows
   [`templates/TEAM-README.md`](../templates/TEAM-README.md).
2. **A 30-second video** made with Claude's help. See below.
3. **The submission form**, with these fields:

| Field | What to put |
|---|---|
| Team name | The name you registered on the hub |
| Lane | 1 Find it, 2 Clear it, 3 Fund it, or your own direction |
| One-liner | One sentence: who it is for and what it does |
| The real user, before and after | Who they are. What is hard today. What changes with your tool |
| What it does | A short description |
| How to try it | Steps, or a link. Someone not on your team should be able to follow them |
| Sources and assumptions | The laws, datasets and programs you used, and every number you assumed |
| Public repo URL | Your GitHub repo |
| 30-second video URL | A link anyone can open |
| Live demo URL | Optional. If you have one running somewhere |
| Members | Everyone on the team |
| Contact name and email | One person. Use the same email each time you edit |

## The 30-second video

Made with Claude's help. For example, Claude writes the script or storyboard, or builds the demo
that the video shows. Use any screen recording tool. Put it somewhere with a link anyone can open:
YouTube unlisted, Loom, or Drive with link sharing on. Put the link in your README too.

Thirty seconds is short. One user, one problem, the tool working, the result.

## New to GitHub?

- One teammate with a free GitHub account is enough.
- No code in your project? A repo with just the README and your files is fine. On GitHub, choose
  **Add file**, then **Upload files**.
- Stuck? Find an organizer well before 2:30.

## Before you submit

- [ ] The repo is public.
- [ ] The README says who it is for, what it does, how to try it, and what is real versus mocked.
- [ ] Sources and assumptions are shown. Every made-up number is labelled.
- [ ] There is no personal information anywhere in the repo or its history.
- [ ] There are no API keys or passwords in the repo or its history.
- [ ] The video link opens when you are signed out.
- [ ] Someone who is not on your team could follow the README and run it.

## After 2:30

Judges shortlist from all submissions. Finalists are announced at 3:00 and present live in the
auditorium. Keep your project running and ready to share either way. Judges deliberate at 4:00.
Winners and photos at 4:15.

## After today

Your team owns what it built. Keep the repo public.
