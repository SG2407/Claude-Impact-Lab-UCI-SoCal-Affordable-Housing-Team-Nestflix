15. FINANCIAL ENGINE REQUIREMENTS
============================================================

This part is critical.

Implement financial formulas as pure Python functions with unit tests.

A. TOTAL COST

total_cost = sum(project_cost_items)

B. INITIAL GAP

initial_gap = max(
    0,
    total_cost
    - affordable_buyer_price
    - existing_subsidies
    - earned_revenue
)

C. SECURED GAP

secured_gap = max(
    0,
    initial_gap
    - confirmed_additional_funding
)

D. SIMULATED GAP

scenario_gap = max(
    0,
    secured_gap
    - proposed_additional_funding
)

E. SURPLUS

If proposed or confirmed funding exceeds the gap, report surplus separately.

Do not display negative remaining funding as an additional need.

F. MONTHLY MORTGAGE PAYMENT

For monthly rate r, principal P and payment count n:

payment = P * r * (1+r)^n / ((1+r)^n - 1)

When r = 0:
payment = P / n

Use interest-rate percentages correctly.

G. MAXIMUM LOAN PRINCIPAL

Calculate the inverse of the mortgage payment formula using a fixed monthly principal-and-interest budget.

Subtract estimated non-mortgage housing expenses before computing loan capacity.

Handle zero or insufficient budget safely.

H. RATE SENSITIVITY

For the example rate analysis:
- Start from an assumed baseline affordable purchase price.
- Calculate the mortgage payment using the baseline rate.
- Hold that payment capacity constant.
- Recompute the affordable mortgage principal using the new rate.
- Recalculate affordable purchase price.
- Recalculate the project gap.

Assume down-payment percentage and non-mortgage costs remain fixed unless explicitly changed.

Label this as an illustrative scenario model.

I. FUNDING RESTRICTIONS

Do not treat a repayable loan as an unconditional grant.

Do not add unverified program funding to confirmed funds.

Do not double-count buyer down-payment assistance as both developer subsidy and buyer purchase price.

Use clear financing categories.
